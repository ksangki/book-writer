# 편집 노트 — 「거두는 체계」 (ax-system)

> editor(Phase 4)가 통합 과정에서 발견한 것 중 **본문 직접 수정 범위를 넘는 것**을 기록한다.
> 수신자: Phase 4.5 `manuscript-reviewer`, 그리고 오케스트레이터.
> 원칙 — 장 본문은 final이므로 editor는 전환부·용어 정합 외의 내용을 고치지 않았다. 고칠 것은 저술가에게 요청하거나 여기 남겼다.

## 1. 저술가에게 요청해 해소한 것

### 1-1. 「벽」 개수 불일치 (1장·10장) — 요청 발신

**발견:** 1장 소절 제목이 `앞으로 부딪힐 여덟 개의 벽`인데 같은 소절의 표 1은 **9행**이다. 10장 매듭 소절도 `여덟 개의 벽을 지나왔다`로 열지만, 바로 다음 문단이 되짚는 단계는 **아홉 개**다(재고 → 관문 → 절차 → 등록 → 청구서·계층 → 가역성·등급 → 측정 → 협상 → 폐기).

**원인:** 계획서 카드 12는 8칸이지만, 같은 계획서가 "카드 12에 없는 축(SOP)이 3·4장으로 삽입된다"고 명시했다. 1장 표와 10장 매듭 문단은 그 9개를 정확히 반영했고, 어긋난 것은 **수사(數詞)뿐**이다.

**정합 근거가 9쪽이다:** 도구가 9개(2~10장 각 1개), 1장 193행의 도구 목록도 9개, 부록 A도 9항목.

**조치:** chapter-writer-A(1장)·chapter-writer-C(10장)에 각각 `여덟` → `아홉` 국소 수정을 요청했다. 표·본문·도구 목록은 손대지 않도록 명시했다.

**✅ 해소 완료 (검증됨).** 두 저술가가 반영했고 통합 원고를 재생성했다. 확인 결과:

- 1장 175행 = `## 앞으로 부딪힐 아홉 개의 벽`, 표 1의 숫자 행 **9개** 유지
- 10장 161행 = `아홉 개의 벽을 지나왔다`
- 10장의 **`여덟 장`(9행, 2~9장을 가리킴)과 `아홉 장`(133·167·173행, 1~9장을 가리킴)은 원문 그대로 보존**됐다 — 이 둘은 정확한 표현이므로 함께 바뀌지 않는 것이 중요했고, 실제로 바뀌지 않았다
- 두 장의 자수 무변동(15,370 / 12,135) — 수사 한 단어만 교체됐다
- `04_manuscript.md` 전량에서 `여덟 개의 벽` **0건**, `아홉 개의 벽` 2건(1장 제목·10장 매듭)

## 2. 계획서 자체의 내부 불일치 (구조 판단 필요 — editor 범위 밖)

### 2-1. 뒷부속 분량 예산이 뒷부속 명세와 모순된다

`02_plan.md §분량 규약`은 "부록·참고문헌 약 2,000자"로 잡았으나, 같은 계획서 §앞부속·뒷부속은 부록 A에 **워크시트 9항목**을, 부록 B에 **축별 참고문헌 + 출처 성격 라벨 + 접근일 명기**를 요구한다. 표 템플릿 9벌과 서지 목록이 2,000자에 들어가지 않는다.

**editor의 판단:** 명세를 채택하고 예산을 초과했다(실제 26,755자 — 부속 검증 정정으로 서지가 보강되며 늘었다). 근거와 계측은 `length_report.md §앞부속·뒷부속`에 예외로 명시했다. 계획서 수치를 고치는 것은 이 원고의 범위를 넘는다.

### 2-2. 카드 12의 8칸과 실제 목차의 9벽 (위 1-1의 뿌리)

수사만 고쳐 해소했지만, 계획서 층위에서는 카드 12(8칸)와 실제 구성(9벽)이 병존한다. 재실행 시 계획서의 카드 12 대조표에 SOP 축을 명시적으로 편입해 두면 같은 drift가 재발하지 않는다.

## 3. 용어 — 통일하지 않고 유지한 것과 그 사유

통권 대조 결과 **표기 충돌로 판정할 항목은 없었다.** 다만 아래 셋은 표면상 유사어가 병존하므로 판단 근거를 남긴다.

| 표기 | 분포 | 판정 |
|---|---|---|
| **등록부 / 등록소 / 원장** | 등록부 = 전 장(지배 표기) / 등록소 = 5·10장 / 원장 = 5·6장 | **유지.** 세 표기가 서로 다른 층위를 가리킨다 — `등록부`는 항목을 담는 장부, `등록소`는 「그 등록소도 죽지 않는가」라는 반문(반론 N) 갈래에서만 쓰이는 제도·장소로서의 지칭, `원장`은 런타임 발급 주체와 대비되는 조직 보유 기록(6장 "발급 주체는 런타임이되, 원장은 조직이 갖는다")이다. 반론 N 갈래는 5장·10장에서 `등록소`로 일관되며 섞이지 않았다. |
| **디지털 워커 / 디지털 직원 / 디지털 노동 / 디지털 인력** | 5장 = 워커·노동·인력 / 6장 = 직원 | **유지.** 전부 인용 대상 원문의 표현이다(5장은 "digital worker"·"디지털 노동"·"디지털 인력"을 쓴 벤더 발표, 6장은 "digital employee"를 쓴 은행 보도자료·경영진 발언). `fact_rules_active.md` **R3-2(따옴표·블록 인용 안에서는 원문 충실, 공개 고유명을 교체·익명화하지 않는다)** 가 통일을 금지하는 자리다. 임의로 한쪽으로 정렬하면 사실 오류가 된다. |
| **섀도 AI / 섀도 개발 / 섀도 에이전트** | 2장 / 1장 / 10장 | **유지.** 접두어가 통일돼 있고 지칭 대상이 각각 다르다(미승인 도구 사용 / 과잉 통제가 유발하는 우회 개발 / 보안 승인 없이 만들어진 자동화·서비스 계정). |

`사번`·`식별자`·`스폰서`·`관문`·`가역성`·`자율성 계수`·`신뢰도 등급` 등 핵심 용어는 전 장에서 단일 표기로 유지됐다.

## 4. 전환부 — 점검 결과 (수정 없음)

아홉 개 이음매를 계획서의 브리지 설계와 대조했다. **전량 통과이며 editor가 문장을 삽입·수정한 곳은 없다.**

| 이음매 | 앞 장 클로징 | 뒤 장 오프닝 | 판정 |
|---|---|---|---|
| 1→2 | 열린 질문("목록은 몇 줄인가, 몇 개를 열어봤는가") | 충격 수치(에이전트 워싱) | ✅ 질문을 밖의 풍경이 받는다 |
| 2→3 | 적용 과제("두 번째 열의 빈칸이 다음 장의 출발점") | 인용(문서가 죽으러 가는 곳) | ✅ 계획서 브리지 그대로 |
| 3→4 | 한 문장 여운(절차 문서의 수명) | 수사적 질문(안 지켜지면 누구 문제인가) | ✅ 4장 세 번째 문단이 3장을 명시 회수 |
| 4→5 | 변주된 이음말("등록한다는 건 무엇을 적는다는 뜻인가") | 5장 제목이 그 문장 | ✅ 최상 |
| 5→6 | 열린 질문("계정을 만들면 청구서가 붙는다") | 상황 가정(다음 날 아침 라이선스 문의) | ✅ 최상 |
| 6→7 | 한 문장 여운(청구서 앞에서 모양을 갖춘다) | 충격 사실(28% 충돌) | ✅ 6장 중반이 등급을 예고해 둠 |
| 7→8 | 적용 과제 + 질문("성과를 잴 기준은 아직 없다") | 인용(1만 시간 = 2만 명의 30분) | ✅ 8장 도입이 진단을 전제로 접수 |
| 8→9 | 경고형("누군가는 그 숫자로 정원을 계산할 것") | 상황 가정(커서가 깜빡이는 채로 손이 멈춘다) | ✅ 최상 |
| 9→10 | 적용 과제(선언문을 고쳐 써 보라) | 앞 장 콜백 2겹(9장 약속 → 1장 거두는 체계) | ✅ 계획서 S4 설계 그대로 |

- **획일적 이음말 없음.** "다음 장에서는 ~를 살펴보자" 형태로 닫힌 장은 하나도 없다.
- **「이 장의 핵심」** 은 2·5·7·8장 네 장에만 있고 헤딩이 정확히 `### 이 장의 핵심`이다(계획서·스타일 지침 일치).
- **파트 구분면 5개**는 editor가 새로 공급한 유일한 본문 지면이다. 파트당 한 줄 명제만 두었고 목차 재진술("이번 파트에서는 ~")은 쓰지 않았다.

## 5. 크로스 레퍼런스 — 검증 결과

장 간 참조 90여 건을 전수 추출해 지목한 장의 실제 내용과 대조했다. **1-1 외의 오참조는 없었다.** 표본 검증 기록:

- 1장 → 8장("우리가 만든 숫자도 같은 방식으로 반박당한다") = 8장 「자기 숫자부터 의심한다」 ✅
- 1장 → 5장("등록부를 설계할 때 다시 쓰인다", 골든 패스) = 5장 「등록이 운영 경로 위에 있어야 산다」 ✅
- 4장 → 1장("세 가지 밑바탕 가운데 버전 관리가 첫 자리") = 1장 DORA 세 조건의 첫 항목 ✅
- 6장 → 1·4장("1장에서 예고하고 4장에서 다리를 놓았던 것이 이 칸") = 1장 SOP 자격 기준 예고 + 4장 말미 회수 ✅
- 7장 → 1장("1장에서 본 두 실패 모드") = 강제된 플랫폼의 우회로 / 과잉 통제의 섀도 개발 ✅
- 8장 → 5장("여덟 칸 중 사람의 개입 지점 칸") = 5장 스키마 5번 ✅
- 10장 → 5장("36개 필드"), → 6장("자격 증명 교체 질문"), → 3장("감지 장치는 3장에서 만들었다") 모두 ✅
- 9장 → 8장("앞 장에서 본 실험", 이메일 −31% / 회의 변화 없음) = 8장 딜런 등 ✅

「이 책만 읽어도 성립한다」 규약도 확인했다 — 전작을 명시적으로 호출한 서술은 본문에 없다(서문만 3부작의 자리를 밝히며, 전작을 읽어야 이해되는 서술은 쓰지 않았다).

### 11-1. BLOCK-1 — 1장의 클라인·소라 장치 선취 제거 (권고 1안)

**문제.** 클라인·소라(1996, *AMR* 21(4)) 장치가 1장과 9장에 **두 번 통째로** 전개됐다 — 이론 도입·변수 둘·진단 도구·결과 넷·페이오프가 전부 겹쳤다.

**조치.** `01_final.md` 139·141행(두 단락)을 한 단락으로 줄였다. 장치의 다섯 요소를 모두 걷고 남긴 것은 ① 논문 귀속 한 절 ② 앞 절의 「사용률을 목표로 삼지 말자」를 받치는 한 문장 ③ **9장으로 넘기는 명시적 포인터** ④ 1장 고유 결론("조건이고 제도다. 과제 목록은 여기 없다")이다. 리뷰어 요구("둘 중 한 곳에서만 장치가 전개되고 다른 한 곳은 명시적 참조가 되어야 한다")를 이 형태로 충족했다.

### 11-2. BLOCK-2 — 7장의 "1장에서 본 두 실패 모드" 오참조 정정

**문제.** 7장 156행이 「과잉 규제→우회 / 과소 규제→사고」를 **대칭 쌍**으로 적고 1장에 귀속시켰다. 1장의 두 모드(원고 L239)는 **둘 다 과잉 통제 방향**이고(강제된 플랫폼→우회로 / 과잉 통제 거버넌스→섀도 개발), 1장은 같은 줄에서 *"두 난간이 사실 같은 난간이다"* 라고 못 박는다. 뒤쪽 절반이 1장에 없었다.

**더 무거운 쪽.** 1장 275~279행은 *"이미 통제 불능으로 번지고 있다"* 류 긴급성 서술을 **의도적으로 거절**했다(*"자기 첫 장에서 긴급성을 부풀리면 그 순간 자격을 잃는다"*). 7장의 콜백은 **1장이 쓰지 않기로 한 주장을 1장에 귀속**시켰다 — 책이 자기 사실 규율을 어기는 형태다.

**조치.** 1장 귀속을 과잉 통제 한 방향으로 정확히 줄이고 그 내용을 문면에 박았다(*"1장에서 본 실패 모드 — 강제와 과잉 통제가 우회로와 섀도를 낳는다 —"*). 과소 규제 쪽은 **1장 귀속 없이 7장 자체 논변**으로 세웠다 — 같은 절 154행이 이미 단계별 통제 요건(자율 단계 = 지속 모니터링·신속 롤백·서킷 브레이커)을 적어 뒀으므로, *"관찰 단계의 통제만 걸어두면 그중 아무것도 없다"* 는 구조적 서술로 받았다. **"사고가 일어나고 있다"는 경험적 주장을 쓰지 않았다** — 1장의 규율을 7장에서도 지킨다.

7장 자수 15,186 → 15,355(+169자), −4.03%로 기준 내.
