# 운영자 학습 루프 — 인간의 학습 환경을 하네스의 설계 요소로

**출처:** Toby/AI, "에이전트의 실행 환경만이 아니라, 개발자의 학습 환경도 설계 대상이다" (2026-07-01)
— https://codex.epril.com/designing-developer-learning-environments-for-ai-agents

**도입 버전:** 하네스 v1.9.0

## 왜

아티클의 논증은 이렇다. 업계는 에이전트의 피드백 환경(컴파일러·테스트·린터·리뷰 계층)은 집요하게 설계하면서, 그 출력을 최종 승인하는 인간의 역량이 어떻게 형성·유지되는지는 설계하지 않는다. 그런데 두 루프의 성질은 비대칭이다 — **에이전트의 피드백 루프는 세션과 함께 증발하지만, 인간의 학습 루프는 경력에 복리로 누적된다.** 인지 작업을 통째로 위임하면 위임한 만큼 배우지 못한다는 실증(Anthropic 실험: 완전 위임 그룹의 이해도 손실, 최대 격차는 디버깅)이 나왔고, 하네스의 최종 품질 게이트가 인간의 판단력인 이상, 기본 작업 방식이 그 판단력의 원료를 고갈시킨다면 그것은 개인 의지의 문제가 아니라 **설계 결함**이다. 설계 결함은 설계로 고친다.

이 하네스에서 인간 = **운영자**(책을 발주하고 승인하는 사람)다. 운영자가 맡는, 형식화되지 않는 판단들:

- 이 책의 구성이 대상 독자에게 맞는가 (Phase 3 계획 승인)
- 이 논지·사실·문체가 출간 가능한 수준인가 (에스컬레이션 판정)
- 이 책을 세상에 내놓을 것인가 (최종 수락)

기계 게이트(fact-checker·continuity-keeper·manuscript-acceptance)가 아무리 두꺼워져도 이 판단은 남는다. 운영자 학습 루프는 이 판단력의 원료 — 생성 경험, 예측 오류, 설명 시도 — 가 하네스를 사용하는 중에도 계속 공급되게 하는 장치다.

## 기존 '하네스 학습 루프'와의 구분

| | 하네스 학습 루프 (v1.8.0) | 운영자 학습 루프 (v1.9.0) |
|---|---|---|
| 학습 주체 | 하네스 자신 | 인간 운영자 |
| 매체 | `book-lessons.md` append-only 레코드 | 상호작용 기본값 + 표적 연습 + 위임 다이얼 |
| 원리 | 책 산출 교훈의 누적 메모리 | 인지 작업의 첫 시도를 인간이 소유 |
| 소비 지점 | Phase 0 soft note | Phase 0·3·4·완료 보고의 터치포인트 |

둘은 별개이며 보완적이다. 하나는 도구가 배우고, 하나는 사람이 배운다.

## 세 겹의 설계 (아티클 4절 대응)

### 1겹 — 흐름 안: 상호작용 기본값 (항상 켜짐)

원리: **인지 작업의 첫 시도를 인간이 소유한다.** 추가 시간 ~0.

- **선판단 후공개 (Phase 3):** 계획을 보여주기 *직전*, 운영자에게 "이 주제·독자라면 어떤 챕터 흐름을 기대하시나요? (한두 줄, 건너뛰어도 됩니다)"를 초대한다. 스케치가 오면 계획 제시 때 **운영자 예상과 갈라진 지점**을 짚어준다 — 예측 오류는 가장 강한 학습 신호다. 생성 효과(generation effect)를 확보하는 가장 싼 방법이다.
- **설명 동봉 (Phase 2 + 완료 보고):** `02_plan.md`에 "설계 근거" 섹션을 의무화한다 — 채택 이유와 함께 **진지하게 고려했다 기각한 대안 구조 2개 이상 + 기각 사유**. 완료 보고에도 구조적 선택 요약을 동봉한다. "왜 이 방식인지, 어떤 대안을 기각했는지"를 함께 받는 것이 실험에서 고성과 집단의 상호작용 패턴이었다.
- **설명 가능성 자문 (완료 보고):** 보고 말미에 자가 점검 한 줄 — "이 책의 핵심 논지를 남에게 한 문단으로 설명할 수 있는가? 막히는 지점이 직접 읽을 지점이다." 자문 전용이며 판정하지 않는다.

### 2겹 — 흐름 밖: 표적 검수 연습 (완료 보고, 자문)

원리: **총량이 아니라 규칙성과 표적.** 파이프라인 로그가 취약 지점을 지목한다 — "데이터가 짚어준 취약 지점에 집중한다"의 하네스 버전.

Phase 5 완료 보고에 **직접 검수 표적**을 제안한다 (production 1개 / learning 3개). 표적 선정은 로그 기반:

| 신호 | 제안하는 연습 |
|------|--------------|
| `factcheck_log.md`에 ⚠️(출처 없음)·🕒(신선도)·에스컬레이션이 몰린 챕터 | 그 챕터의 사실 주장 N건을 원출처에서 직접 확인 |
| `style_log.md`에서 왕복이 가장 많았던 챕터 | 체크리스트를 옆에 두고 AI 판정 없이 직접 읽고 판정한 뒤 로그와 비교 |
| `05_acceptance.md`에서 아슬하게 통과한 기준 | 그 기준 하나로 통권 스팟 체크 |

15~30분 안에 끝나는 크기로 제안한다. 수행 여부를 추적하거나 잔소리하지 않는다.

### 3겹 — 메타: 위임 다이얼 (Phase 0)

원리: **"나는 지금 생산 모드인가, 학습 모드인가."** 멘탈 모델이 없는 영역에서는 위임을 낮추고, 숙달한 영역에서는 공격적으로 위임한다.

- `delegation_mode`: `production`(기본) / `learning`
- **결정 규칙:** 사용자가 `모드: 학습`을 명시하거나 "이 주제를 공부하려고 / 잘 몰라서" 류의 명확한 학습 신호가 있을 때만 `learning`. **신호가 없으면 묻지 않고 `production`** — 기존 동작 보존. Phase 0에서 어차피 AskUserQuestion을 쓸 일이 있으면 그 질문에 다이얼 확인을 편승시켜도 된다 (추가 왕복 금지).
- editor가 `book_manifest.json`의 `delegation_mode` 필드에 기록한다 (`genre`와 같은 취급 — 재실행 결정성. 누락 시 `production`).
- **learning 모드에서 추가되는 것:**
  1. Phase 3 선판단 초대가 기본 단계로 승격된다 (여전히 건너뛰기 허용)
  2. Phase 4에서 **첫 챕터 final** 산출 시 운영자에게 알리고 `profiles/{genre}/style-checklist.md`와 함께 직접 읽기를 권한다. 피드백이 오면 반영하고, 없으면 그대로 진행한다 (비블로킹 — 저술 풀을 멈추지 않는다)
  3. 완료 보고의 직접 검수 표적이 1개 → 3개
- `production` 모드는 현행 동작 그대로 + 1겹의 저비용 기본값만 적용된다.

## 불변 원칙

1. **비블로킹.** 모든 터치포인트는 자문 전용이다. 운영자가 응답하지 않거나 자율 실행 중이면 조용히 생략하고, 완료 보고에 해당 노트만 남긴다. 학습 루프가 파이프라인을 멈추게 해서는 안 된다 — 품질을 막는 게이트는 별도로 존재한다 (fact/continuity/acceptance).
2. **추가 왕복 최소화.** 질문은 기존 상호작용 지점(Phase 0 확인·Phase 3 승인·완료 보고)에만 편승한다. 새 대기 지점을 만들지 않는다.
3. **강제하지 않는다.** 학습은 운영자의 선택이다. 하네스는 기본값과 신호를 설계할 뿐, 수행을 측정하지 않는다.

## 터치포인트 매핑

| Phase | production (기본) | learning |
|-------|------------------|----------|
| 0 | 다이얼 신호 감지 (질문은 편승만) | 동일 |
| 3 (계획 승인) | 승인 요청에 선판단 초대 한 줄 편승 + 계획에 설계 근거 동봉 | 초대가 기본 단계 + 갈라진 지점 명시 |
| 4 (저술) | — | 첫 챕터 직접 읽기 권유 (비블로킹) |
| 5 (완료 보고) | 설명 가능성 자문 한 줄 + 검수 표적 1개 | 검수 표적 3개 |

## 갱신 규칙

이 문서가 운영자 학습 루프의 정전(canonical spec)이다. 터치포인트를 추가·변경할 때는 이 문서를 먼저 갱신하고, 오케스트레이터·에이전트 정의를 여기에 맞춘다.
