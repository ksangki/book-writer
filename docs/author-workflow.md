# 저자 워크플로: 주제 하나에서 공개·홍보까지

이 문서는 한 권의 책이 주제 한 줄에서 출발해 공개 저장소와 링크드인 게시물이 되기까지의 전 과정을 정리한 정본이다. 2026년에 16권(시리즈 15권과 종합편)과 후속 신간을 내며 실제로 반복한 순서를 그대로 옮겼다. 오케스트레이터(`book-writing-orchestrator`)가 Phase 0~8로 실행하고, 이 문서는 각 단계에서 저자가 무엇을 정하고 무엇을 맡기는지를 적는다.

## 한눈에

| 단계 | 하는 일 | 저자가 정하는 것 | 산출물 |
|---|---|---|---|
| 0. 브리프 | 주제·독자·출발점을 적는다. 저자가 자리를 비우면 자율 모드로 간다 | 주제, 1인칭으로 써도 되는 사실, 쓰지 않을 이름 | `00_brief.md`, `decisions.md` |
| 1~3. 리서치·계획 | 리서처 병렬 → 레퍼런스 합성 → 계획 → 계획 검토 | 계획 승인(자율 모드면 plan-reviewer 2회로 대신) | `01_reference.md`, `02_plan.md`, `03_review_log.md` |
| 4. 저술·검수 | 장 묶음 병렬 저술 → 사실 확인 → 그림 → 통합 → 교정 → 수락 게이트 | 미해소 사실 오류의 처리 | `04_manuscript.md`, `05_acceptance.md` |
| 5. 표지·EPUB | 표지 생성, EPUB 빌드, epubcheck | 표지 시안 선택 | `{제목}-v{ver}.epub`, `.md` |
| 6. 웹·발표·영상 | 웹판, 1시간 발표자료, 오프닝 영상(showreel), 홍보 영상(brag) | 영상 속도·소리 | `{slug}/site/`, `media/opening.mp4` |
| 7. 교차 검토 | GPT 편집 검토·삽화 수용, Codex 직접 검토, 원문 재대조 후 반영, 판 올림 | 반영 범위, 삽화 위치 | `_v{이전}/`, `07_cross_review.md`, `illustrations/` |
| 8. 공개·홍보 | 공개 저장소·Pages 배포, 라이브 확인, 링크드인 글·캐러셀 | 공개 여부, 게시 문구 | `ksangki.github.io/{repo}/`, `linkedin/` |
| 이후 | 정오(errata) 패치, 시리즈 링크 갱신, 종합편 반영 | 정오 판 낼지 | `v{x}.{y}.{z+1}` |

## 0. 브리프와 자율 모드

- 저자가 "검토 없이 끝까지"처럼 자리를 비우겠다고 하면 **자율 모드**다. 질문을 할 수 없으니 `{slug}/00_brief.md`에 저자가 직접 말한 사실만 적고, 모든 에이전트가 이 파일을 먼저 읽게 한다.
- 브리프에 반드시 넣는 것: 저자 1인칭으로 쓸 수 있는 사실(문장 그대로), 쓰지 않을 이름(회사·부서·인물·사내 시스템·사내 용어·미공개 수치), 공개된 해외 출처는 실명으로 쓴다는 규칙, 표기 규칙(엠대시 금지, 권수·기간 아라비아 숫자, '재다' 대신 '측정'), 외부 전송·push 금지.
- 저자에게 물을 수 없는 판단은 `decisions.md`에 근거와 함께 적는다. 저자가 돌아오면 완료 보고에 "대신 내린 결정"과 "정해 주실 것"을 따로 묶어 올린다.
- 파(wave) 사이에 생긴 문체·사실 지침은 `style_guide_active.md`에 누적해 다음 저술가가 읽게 한다.

## 1~5. 저술 파이프라인

오케스트레이터 스킬의 Phase 1~5를 그대로 따른다. 저자 관점의 요점만 적는다.

- 계획 검토는 자율 모드에서 plan-reviewer 2라운드로 저자 승인을 대신한다. 이때 Critical 지적은 반드시 반영하거나 유보 사유를 남긴다.
- 사실 오류는 문체 이견과 달리 저술가 재량으로 덮지 않는다. 통권 수락 게이트가 BLOCK이면 한 번 고치고 다시 받는다.
- 판권(`## 판권`)에는 판본·발행일·판 이력·제작 고지를 둔다. 제작 고지에는 에이전트가 맡은 일과 저자가 정한 일을 나눠 적고, 생성 이미지(표지·삽화)를 쓰면 그 사실을 적는다.

## 6. 웹·발표자료·영상

- 웹판은 `build_web.py`가 EPUB에서 만든다. 본문의 맨 주소(https://…)는 자동으로 링크가 되고 바깥 링크는 모두 새 창으로 열린다.
- 발표자료는 수락된 원고에서만 내용을 가져온다. 모든 내용 슬라이드에 '쉽게 말하면' 한 줄을 단다.
- **오프닝 영상(showreel):** 발표 맨 앞이나 웹판 표지 아래에 거는 60~90초 영상이다. `showreel` 스킬로 만들고 `site/media/opening.mp4`·`opening.jpg`에 둔 뒤 매니페스트 `web_videos`에 캡션을 적는다. 화면 글자는 한 화면에 한 문장 안팎으로 두고, 그 문장을 소리 내어 두 번 읽을 시간(한국어 기준 약 4~5자/초, 최소 3초)을 준다. 2026-11 종합편에서 "글씨를 다 읽기 전에 넘어간다"는 피드백으로 60초를 90초로 늘렸다.
- 홍보 영상(brag)은 약 20초짜리 짧은 소개다. 오프닝 영상과 역할이 다르다.

## 7. 교차 검토 (GPT · Codex)

책을 만든 에이전트와 다른 모델에게 원고를 한 번 더 읽힌다. 같은 모델의 수락 게이트가 놓친 것을 다른 눈이 잡는다. 실제로 매 권 새 오류가 나왔다.

1. **GPT 검토 받기:** 저자가 ChatGPT에 웹판이나 EPUB을 주고 받은 결과 폴더(`편집검토.md`·`문체-검토.md`, `삽화/`·`media/illustrations/`, 배치안)를 알려 주면 그 폴더를 읽는다. 같은 이름의 폴더가 여럿이면 md5로 이미 반영한 것과 겹치는지 먼저 본다.
2. **순서:** 백업(`_v{이전}/`) → GPT 지적 재대조·반영 → 이번 판 diff → Codex 검토 → Codex 지적 재대조·반영 → 판·빌드·기록. 반영한 결과를 다른 모델이 다시 보게 한다.
3. **Codex 직접 검토:** `cross-review` 스킬의 `codex_review.sh`로 로컬 Codex CLI를 읽기 전용으로 부른다. 프로젝트 전체가 아니라 **검토 전용 폴더**(원고 사본, diff, 필요한 연구 발췌, 전송 가능한 저자 사실 목록)만 열어 주고, 삽화 이미지를 첨부한다. 저자 사실 목록은 금지 이름을 `grep`으로 걸러 넣는다. 목록이 빠지면 Codex가 맞는 문장도 "지어낸 경험"으로 지적한다.
4. **재대조 후 반영:** 검토서의 사실 지적은 그대로 넣지 않고 `research/*.md`와 1차 출처에 다시 대조한다. 검토서가 틀린 경우와 검토서가 놓친 오류가 매번 나왔다. 기각한 지적도 근거와 함께 `07_cross_review.md`에 남긴다.
5. **판과 빌드:** 문장·수치·삽화가 바뀌면 minor(v1.0.0 → v1.1.0), 오탈자·링크만이면 patch. 식별자(`urn:uuid`)는 유지한다. EPUB·책 소개 md·`site/BOOK.md`·웹·덱을 함께 새 판으로 맞춘다.
6. **여기서 멈춘다.** 이미 공개된 책이라도 새 판을 다시 올리는 것은 저자가 그 판의 공개를 요청할 때다.

## 8. 공개와 홍보

- 공개는 저자가 원고·비식별을 확인하고 요청할 때만 한다. 책마다 공개 저장소(`ksangki/{repo}`)를 만들고 Pages로 연다. EPUB 경로는 `ksangki.github.io/{repo}/epub/{파일}`로 통일한다.
- 첫 공개는 점검 → 저장소 생성 → 라이브 확인, 재배포는 점검 → 바뀐 파일만 반영 → 라이브 확인 순서다. 다시 올릴 때는 `rsync --delete`와 `git add -A`를 쓰지 않는다. 먼저 `git log`·`git status`로 저자가 다른 세션에서 넣은 파일(오프닝 영상 등)이 있는지 본다.
- 올린 뒤에는 라이브 주소에서 표지·영상·삽화·EPUB 내려받기·새 창 링크가 실제로 동작하는지 확인한다.
- **링크드인:** 에필로그나 결론 중심의 짧은 글(첫 두 줄에 질문이나 결론, 본문 5~8줄, 링크 1개)과 캐러셀(1080×1350 이미지 6~10장 + PDF)을 만든다. 영상 하나만 올린 게시물보다 여러 장 이미지(문서형 캐러셀)가 피드에서 머무는 시간이 길어 노출이 잘 되는 편이었다. 캐러셀은 표지 → 질문 → 핵심 3장(삽화 위에 한 문장) → 도구 하나 → 읽는 곳 순서다.

## 이후: 정오와 시리즈 관리

- 다른 책의 사실 확인 중 앞 책의 오류를 찾으면 그 자리에서 고치지 않고 "정오 후보"로 보고한다. 저자가 정하면 patch 판(v1.1.0 → v1.1.1)으로 낸다.
- 정오를 내면 그 책을 인용한 종합편·후속편의 「더 읽을 곳」 판본 표기도 함께 갱신한다.
